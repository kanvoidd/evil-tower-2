# Evil Tower 2

Карточный рогалик про подъём по башне (Phaser 3 + TypeScript + Vite) для Яндекс Игр. Портретная мобильная раскладка 720×1280, на десктопе — по центру окна.

**10 этажей по 5 комнат.** Состав каждой комнаты набирается заново при каждом заходе (пул врагов этажа + случайное свойство комнаты). Колода бесконечна: комната заканчивается не зачисткой поля, а нормой убийств — после неё в колоду замешивается карта «Переход», и надо шагнуть на неё. Способности не теряются при метаморфозе, поэтому к финалу линейки в нижней панели боя до десяти кнопок, а дерево — пятнадцать талантов на класс, цепочками разной длины.

## Запуск

Нужен Node.js LTS (20.19+ / 22+).

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # проверка типов + сборка в dist/
npm run zip        # evil-tower-2.zip — архив для консоли разработчика Яндекс Игр
```

Полезные скрипты:

| Команда | Что делает |
|---|---|
| `npm run sim -- warrior 25` | Симулятор баланса: бот проходит все 50 комнат с фармом, выводит win-rate, время и прокачку (`warrior/mage/archer/mercenary`) |
| `npm run selftest` | Самопроверка логики: дерево талантов, способности, статусы, автопрокачка, фазз-тест боя, потоки экранов без Phaser (хаб, лавка, дерево, выбор героя, настройки, реклама) |
| `npm run archtest` | Проверка архитектуры: правила зависимостей между слоями и между доменными областями (`docs/DOMAIN.md`), API браузера в домене, битые импорты, циклы (`-- --graph` — матрицы зависимостей слоёв и областей) |
| `npm run apk:assets` | Собирает игру в офлайн-режиме и кладёт её внутрь Android-проекта |
| `npm run apk` | Собирает `evil-tower-2.apk` (нужен Android SDK; `-- --debug` для отладочной сборки) |
| `npm run store` | Генерирует иконку 512×512 и обложку 800×470 в `store/` (нужен `pip install pymupdf`) |
| `npm run typecheck` | Только проверка типов |

Dev-параметры URL (работают только в `npm run dev`, в сборку не попадают):
`/?reset=1&class=mage&gold=5000&souls=20000&clear=8&tut=1&autoskill=200&weapon=2&armor=1`

## Структура

Код разложен по слоям; зависимости идут только внутрь: `presentation → application → domain`, а `infrastructure` и `composition` подключаются снаружи через интерфейсы (порты). Домен разложен по доменным областям (бой, прогресс героя, каталог, награды …) — карта, язык и публичный API областей в `docs/DOMAIN.md`. Правила и принятые решения — `PROJECT-DECISIONS.md`, неочевидные ловушки — `GOTCHAS.md`, соблюдение правил проверяет `npm run archtest`.

## Как всё устроено и как это править

### Этажи и рогаликовая случайность

- Враги — 60 на 10 этажей (по 4 обычных, элита и босс); их выпускают фабрики этажей (`src/domain/catalog/floors/<этаж>-floor/`). Числа не пишутся руками: у врага есть **этаж** и **роль** (`weak/normal/tough/elite/boss`), а сила считается по кривым `FLOOR_HP`, `FLOOR_ATK`, `FLOOR_GOLD`, `FLOOR_SOULS` (`floors/floor-factory/FloorFactory.ts`). Хотите сделать башню злее — правьте четыре константы, а не полсотни строк. У врагов есть свойства: броня, регенерация, шипы, уворот, ярость, магия, яд.
- `src/domain/catalog/levels/` — комната задаётся не списком врагов, а «рецептом»: пул врагов этажа и разброс количества. `rollRoom()` собирает состав заново при каждом заходе, поэтому одна и та же комната каждый раз играется по-новому.
- **Свойство комнаты** (`MODIFIERS`, `levels/room-modifiers/`) — второй слой случайности: «Золотая жила», «Орда», «Элита», «Проклятие», «Ветхие кости», «Благословение», «Чемпион». Выпадает при заходе и показывается в шапке боя (по наведению — описание).
- Комната закрывается шагом на «Переход», который замешивается после нормы убийств; в колоду подмешаны и пустые сундуки — они растягивают комнату и ничего не дают.

### Способности классов (кнопки на поле боя)

- Способности выпускают фабрики героев (`src/domain/catalog/heroes/<линейка>-factory/`), реестр — `src/domain/catalog/perks/`: одна запись на способность — id, иконка, цена в ресурсе, тип цели, `ability` и её числа `params` (урон, ходы, доли — типы `AbilityParams`); логика — класс способности в `src/domain/combat/abilities/<линейка>/<id>/` (реестр `ABILITIES`), числа он берёт только из `params`. Название и описание — в словарях `src/i18n/ru/perks.ts` и `src/i18n/en/perks.ts`, числа в описании — плейсхолдерами из тех же `params` (`{dmg}`, `{turns}` …).
- **Кнопка «заряжает» способность**, следующее касание поля применяет её к цели. Способности без цели (`target: 'self'`) срабатывают сразу; «Перестановка» магистра требует двух касаний. Кнопки занимают всю нижнюю панель: до пяти в ряд, дальше две полки по пять — у финального класса их до десяти, потому что способности прежних классов остаются (проверяется в `selftest`).
- **Ход врагов, агр** (`retaliate`): отвечает только тот, с кем герой в бою, — враг, которого он в этот ход ударил рукой или способностью (`engaged`) и который стоит рядом. Если же можно было ударить (`canStrike`: рукой, выстрелом, ударом в спину или молнией, на которую хватает маны), а герой шагнул на клетку без врага, бьют враги, до которых достаёт НОВАЯ клетка (`exposed`). Уйти от врага туда, где рядом никого, — бесплатно; «набрать ману» шагами под чужие удары — нет. Доспех снашивается не больше раза за ход (`armorWorn`).
- **Норма и «Переход»** (`quota`, `queueExit`, `finishRoom`): колода бесконечна (`replenish`), поле не пустеет, а комната закрывается только шагом на карту перехода, которая замешивается после нормы убийств (и смерти босса в пятой комнате). Норма не останавливает подкрепление, и добыча, оставленная на поле, теряется — уходить или рисковать ещё ход решает игрок.
- **Забег как в рогалике** (правила — `src/domain/expedition/`: `TowerClimb`, `RoomPayout`, `RecordPolicy`, `RunCarry`; учёт в профиле — `TowerRun` в `src/application/game/`): «Играть» всегда начинает с 1-1, здоровье и ресурс переходят из комнаты в комнату (`BattleInit.carry`, `RoomBattle.carryOut()`), воскрешение за видео и «Возвращение» — по одному на забег. Пройденная комната сразу платит сумку, души и бонус в кошелёк героя; гибель или побег теряют только добычу текущей комнаты. Рекорд героя — сколько комнат он прошёл за один забег (`Profile.recordRun`).
- **У каждого героя всё своё** (`SaveData.heroes`, `Profile.heroSave` / `heroSaveOf()`): золото, души, расходники, доспех и рекорд. Новый герой начинает с нулями. Достижения и таблица рекордов общие (`Profile.bestClimb`). Старые сохранения мигрируют: общий кошелёк достаётся той линейке, которой играли, а число пройденных комнат становится её рекордом.
- **Маг не бьёт рукой вообще** (стратегия атаки линейки `SpellAttack`: `attack.melee === false`): его единственный удар — «Удар молнии» по кнопке по соседней карте, 250 % урона заклинанием за 3 маны. Мана восстанавливается по 1 за ход (`resRegen`), поэтому каждый удар чисто отнимает 2 единицы: полного запаса (14) хватает примерно на семь ударов подряд, дальше — шаг в сторону или зелье восстановления. Скидка «Экономия маны» не опускает цену ниже 2 (`PERK_COST_FLOOR`), иначе молния окупалась бы восстановлением. В забег герой выходит с полной шкалой, дальше она переносится из комнаты в комнату. Перезарядки (`PerkDef.cooldown`): «Магический выстрел» 1 (бьёт только через карту), «Цепная молния» 2, «Перестановка» 5, «Жребий колоды» 4, «Поджог» 1 (три тика), «Огненный шар» 3 (без маны), «Детонация» 4, «Взрыв трупа» 1, «Призрачные слуги» 4, «Кукла вуду» 2.
- **«Растерзание»** (`RoomBattle.cornered()` + `swarm()`): если ходить нечем совсем — пустая шкала, враги со всех сторон, ни зелья восстановления, ни артефакта, — карты по очереди рвут героя насмерть. Проверка идёт в конце хода, уже после регенерации. Воскрешение возвращает полную шкалу, иначе герой погибал бы повторно тем же кадром.
- **Ход по пустой соседней клетке** разрешён и считается полноценным ходом.
- **Кнопка гаснет**, когда не хватает ресурса, идёт перезарядка, способность уже использована в этой комнате (`once`) или её усиление уже действует (`buffActive`: безумие, жнец, дымовая завеса). Постоянные клейма (приговор, вуду, метка смерти, метка взрыва трупа, метка призрака) не наводятся на цель, которая уже под ними.
- **«Взрыв трупа» и «Призрачные слуги» наводятся на врага:** помеченный враг после смерти рвётся на соседей или встаёт призраком (карта `ghost`), который три хода бьёт врагов вверх/вниз/влево/вправо; призраков не больше двух (`raiseGhost`, `tickGhosts`).
- **Эффекты** — `src/presentation/animations/effects/vfx/Vfx.ts`: двадцать семь семейств (`VFX_STYLES`), у каждой способности свой стиль (`vfx` в фабрике героя); у огня пироманта и некромантии — по четыре разных. Им же рисуются значки перков (`VFX_GLYPH` в `src/presentation/textures/Textures.ts`), поэтому десять кнопок в ряду различимы с одного взгляда.
- **Базовое действие линейки** (`basic: true`) кнопки не занимает и остаётся у всех эволюций: выстрел через карту у лучника, удар в спину у наёмника, удар молнии у мага. Маг именно поэтому бьёт рукой слабо — его удар это молния.
- **Пассивные способности** (`passive: true`) работают сами: «Резня», «Подмена», «Хладнокровие» и другие.
- **Статусы на карточках**: оглушение, горение, яд, клеймо смерти, связь (кукла вуду), приговор, ослабление, метка взрыва трупа, метка призрака. Показываются значками над карточкой.
- Пассивки линеек: воин — самый большой запас здоровья, лучник — самый высокий шанс крита, маг — самый большой запас ресурса и артефакты, наёмник — +20% золота.

### Дерево талантов

- Таланты выпускают фабрики героев (`talentTree` в `src/domain/catalog/heroes/<линейка>-factory/`), реестр — `src/domain/catalog/talents/`: **15 талантов на класс**, по пять на ярус: три пути (урон / здоровье / защита), но цепочками **разной длины** (3-1-1, 1-2-2, 2-2-1, 1-3-1 …), своя раскладка у каждого яруса каждого класса. Цепочки сходятся в общую способность. Значения в `v` **суммарные**: `[20, 30, 40]` значит «+20% → +30% → +40%».
- **Правило ворот:** следующая способность (и метаморфоза) открывается, когда пройдена целиком ЛЮБАЯ ОДНА цепочка яруса. Короткая цепочка — быстрый путь вниз, длинная — больше силы за те же ворота.
- **Таланты-синергии** (`SYNERGY_FX`) меняют уже полученные способности, а не просто прибавляют характеристику, и помечены в дереве молнией: «Живое пламя» пироманта заставляет любую способность поджигать (значит, и цепную молнию мага), «Взрыв плоти» некроманта подрывает труп на соседей. Всего тринадцать видов.
- **Ничего не теряется при метаморфозе** — ни таланты, ни способности: пиромант владеет и заклинаниями мага, и приёмами магистра, и своим пламенем одновременно.
- Дерево строится кодом, отдельного файла с координатами нет: структуру и уровни узлов — `SkillTreeBuilder` (`src/domain/progression/skill-tree/tree-builder/`), экранную раскладку — `SkillTreeLayout` (`src/presentation/views/skill-tree/`).
- Цены — `ISoulPricing` (`src/domain/progression/soul-prices/`), по которым играет игра, — `SOUL_PRICING`: реализация `StageTablePricing` по таблице `SoulPriceBalance` (`src/domain/progression/balance/`) — база `talentBase[ступень][ярус]`, каждый следующий ранг дороже на 35%, способности стоят 6–8 базовых цен своего яруса, метаморфоза 3 500 / 12 000 душ, отказ от финального класса возвращает половину вложенного.

### Баланс и экономика

- **Золото и души разведены:** золото растёт по `FLOOR_GOLD` (под восемь ступеней экипировки), души — по `FLOOR_SOULS` (под дерево талантов, это долгая цель).
- **Доля награды `RUN_REWARD`** (`FloorCurveScaling`, `src/domain/catalog/floors/scaling/`): нижние этажи проходятся в каждом забеге заново и каждый раз платят, поэтому золото и души врагов и бонус комнаты умножены на 0,7.
- Экипировка — `src/domain/catalog/weapons/`, `src/domain/catalog/armor/` (общий каталог — `items/`): 8 ступеней оружия и брони, цены 50 → 15 500. Прочность (100–520 ударов) рассчитана на пару забегов: чинить можно только между ними. Починка (35% цены за полный износ) — постоянный сток золота; сломанный предмет придётся покупать заново.
- **Зелья в лавке — с пределом** (`ConsumableDef.max`: 5 исцеления, 3 восстановления): здоровье переносится между комнатами, и без предела поздний герой брал бы с собой сотню дешёвых зелий.
- Зелье исцеления лечит **долю максимального здоровья** (`ConsumableBalance.healPotionPct`), иначе на десятом этаже оно было бы бесполезно.
- Потолки характеристик — `CAPS` в `src/domain/progression/stats/stats.ts` (крит 60%, уворот 35%, парирование 35%, блок 20%).
- По симулятору (`npm run sim -- <линейка> [повторов] [доля награды]`, `RUNS=`, `SEED=`) бот покоряет башню за 8–15 забегов и 3,5–6,5 часа чистого боя; первый забег голым героем обрывается на первом этаже, дальше каждый забег — на несколько комнат выше.
- После любых правок: `npm run selftest` и `npm run sim -- <линейка>`, а после правок в коде — ещё `npm run archtest`.

### Остальное

- **Иконки/спрайты (jpg/png/bmp/webp):** положите файл в `src/assets/images/` с именем ключа — он подхватится сам, иначе рисуется процедурная заглушка. Ключи: `hero_<classId>`, `cls_<classId>`, `enemy_<id>`, `perk_<classId>_<slot>`, `item_w_<lineage>_<tier>`, `item_a_<tier>`, `item_potion_heal|regen`, `item_artifact`, `ico_gold`, `ico_soul`, `spr_chest`, `spr_gold`, `bg_stone`.
- **Правила добычи:** золото и души комнаты копятся в «кошеле» и уходят в кошелёк героя, когда комната пройдена; гибель или побег их теряют. Сундук даёт золото и с шансом 35 % расходник (ещё один — 8 %); пустой сундук не даёт ничего.
- **Крит:** множитель плавающий — каждый крит бьёт по-новому в диапазоне `CombatBalance.critMulMin … critMulMax`; таланты «крит. урон» поднимают верхнюю границу.
- **«Играть»** в хабе всегда начинает новый забег с 1-1; «Уровни» — карта рекорда, комнату оттуда не запустить.
- **Автоматизация:** на поле боя под каждым расходником — плашка «АВТО» (`src/domain/combat/auto-use/autoUse.ts`). В шапке дерева — кнопка автопрокачки (`src/domain/progression/auto-skill/autoSkill.ts`): купленный вручную талант задаёт путь, и весь путь вниз докупается на все души, включая способности-«ворота». Перед метаморфозой автопрокачка останавливается.
- **Метаморфозы и смена класса:** в окне выбора класса одна запись на линейку — улучшенный класс *заменяет* прежний. «Отмена метаморфозы» осталась функцией дерева (возврат части душ).
- **Сохранения:** версия 2. Сохранения прежней версии игры несовместимы (полностью изменились дерево и способности) и не загружаются.
- **Переходы между экранами** (`src/presentation/navigation/SceneTransitions.ts`): меню открывается «окном», вырастающим из своей кнопки; бой и хаб входят «наездом» камеры; содержимое появляется каскадом.
- **Оформление:** цвета характеристик и путей — `STAT_COLOR` / `PATH_COLOR` (`src/presentation/textures/Textures.ts`), шрифты, палитра и тайминги — `src/presentation/theme/`, числа общих правил — баланс своей области (`src/domain/combat/balance/`, `src/domain/progression/balance/`).

## APK для телефона

Игра целиком офлайн, поэтому её можно упаковать в Android-приложение: `android/` — это готовый проект
из одного экрана, где на весь экран растянут WebView, а сама игра лежит в `assets/www`.

Файлы отдаются не по `file://`, а с виртуального адреса `https://eviltower.localhost` (перехват в
`MainActivity.serve`): под `file://` в современном WebView отключён `localStorage`, а в нём хранится
весь прогресс. Разрешение на интернет приложению не нужно и не запрашивается.

### Вариант 1 — без установки чего-либо: GitHub Actions

Workflow запускается сам при каждом пуше в ветку `claude/**` и при пуше тега `v*`,
а кнопка **Run workflow** доступна после того, как файл попадёт в ветку по умолчанию.

- **Артефакт:** вкладка **Actions** → нужный прогон → блок **Artifacts** → `evil-tower-2-apk`
  (внутри zip лежит `evil-tower-2.apk`).
- **Прямая ссылка для телефона:** запушьте тег — APK автоматически выложится в **Releases**,
  откуда его можно скачать одним касанием с самого телефона:

  ```bash
  git tag v0.2.0 && git push origin v0.2.0
  ```

Дальше откройте файл на телефоне и разрешите установку из этого источника.

### Вариант 2 — локально

Нужен Android SDK (проще всего — Android Studio, он ставит его сам):

```bash
npm ci
npm run apk          # соберёт dist, положит его в android/ и запустит Gradle
```

Готовый файл появится в корне репозитория: `evil-tower-2.apk`. Альтернатива — открыть папку `android/`
в Android Studio и нажать Run (перед этим один раз выполнить `npm run apk:assets`).

APK подписан отладочным ключом — этого достаточно, чтобы поставить его себе на телефон, но не хватит
для публикации в Google Play: там нужен свой keystore и `signingConfig` в `android/app/build.gradle.kts`.

### Что стоит знать

- `minSdk 24` (Android 7.0), `targetSdk 35`, портретная ориентация, полноэкранный режим.
- Реклама и облачные сохранения Яндекса в APK не работают и не нужны: сборка идёт в режиме
  `vite build --mode apk`, где тег `/sdk.js` не внедряется, а игра сама переходит на заглушку.
  Прогресс хранится в `localStorage` внутри приложения.
- Иконка собирается из `store/icon-512.png` (см. `android/app/src/main/res/mipmap-*`).

## Шрифты и лицензии

Заголовки — **Alegreya SC**, интерфейс и числа — **Nunito**; оба под SIL Open Font License 1.1 (свободно, в том числе в коммерческих играх), подключены через пакеты `@fontsource/*` и входят в сборку. Тексты лицензий лежат в `public/licenses.txt` и попадают в архив. Как выбирали: из каталога Google Fonts/Fontsource отобрали шрифты с лицензией OFL **и кириллицей** (Cinzel, Marcellus и другие «фэнтезийные» без кириллицы отпали), сравнили на реальных строках игры — Philosopher, Alegreya SC, Spectral SC, Yeseva One для заголовков и Nunito, Rubik, Golos Text, Fira Sans Condensed, Onest, Alegreya Sans для интерфейса. Alegreya SC даёт книжно-фэнтезийный характер и хорошо держит обводку; у интерфейсных кандидатов мелкий текст и цифры читались не лучше Nunito, поэтому он остался.
- **SVG-иконки** (чёрные, по GDD): `src/presentation/textures/SvgIcons.ts`.

## Яндекс Игры

- SDK подключается только в сборке (`/sdk.js` внедряется плагином Vite); локально работает заглушка.
- Реализовано: `LoadingAPI.ready()`, `GameplayAPI.start/stop`, события паузы/возобновления, `getPlayer().getData/setData` (облачные сохранения + localStorage, побеждает более свежее), rewarded video (воскрешение, ×2 награда, ×2 ежедневная награда, дар башни), interstitial в паузах (не раньше 3-й комнаты, кулдаун 3 мин), язык из `environment.i18n.lang`, лидерборд `rooms` и статистика.
- В консоли разработчика создайте лидерборд с именем `rooms` (опционально) и отметьте использование облачных сохранений.
- Соответствие модерации: звук глушится при потере фокуса и во время рекламы, нет контекстного меню/выделения текста/скролла страницы, прогресс сохраняется сразу, архив < 1 МБ, `index.html` в корне, имена файлов без пробелов и кириллицы (проверяет `npm run zip`).
- Карточка игры: тексты, теги и чек-лист — `store/listing.md`.
